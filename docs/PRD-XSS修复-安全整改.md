# PRD：Web 文件列表页存储型 XSS 修复（安全整改 v1.8）

> 版本：v0.1（待决策）｜ 日期：2026-10-13 ｜ 来源：第三方 WAPT 报告（2026-10-13_STORED-XSS_filename-web-list.md）
> 漏洞定级：**Medium / P3**（CVSS 3.1：AV:N/AC:L/PR:L/UI:R/S:U/C:H/I:H/A:N）——**已确认（CONFIRMED）**，真实浏览器 alert(1) 验证通过

## 1. 漏洞事实（已核实）

- **位置**：`GET /f/{web_token}/` 服务端渲染的文件列表页（`webfiles.py _list_html`）
- **根因**：文件名在**三处 HTML 上下文原样拼接、零转义**：
  1. 元素体：`<span class="fname">📄 {name}</span>`（当前代码 L249，目录链接 L247 同）
  2. 内联事件：`onclick="doRename({path_json},{name_json})"`（L254）——json 的 `"` 可闭合属性
  3. 下载链接 onclick（L252）
- **本地核实**：注入点代码与报告描述完全一致，报告可信。
- **攻击链**：外部交换伙伴上传恶意文件名（如 `<img src=x onerror=...>.txt`）→ 内部员工 Web 打开共享目录 → 同源任意 JS 执行 → **等效该目录完全读/写/删**（fetch 直调 download/upload/delete，HttpOnly Cookie 也挡不住同源调用）
- **边界**：/admin 管理台已用 esc() 转义，不受影响；仅 Web 文件面。

## 2. 影响评估（客观）

| 维度 | 判断 |
|------|------|
| 利用前提 | 攻击者需有目标目录**写权限**的 SFTP 账号 + 受害者用 Web 面打开该目录（UI:R） |
| 当前业务暴露面 | 生产环境 bsftp.greatld.com 对外，含外部文件交换伙伴账号（正是报告所述典型场景） |
| 危害 | 文件内容窃取/篡改/删除（限受害账号目录内）；无法直接偷 Cookie/提权到管理台 |
| 定级合理性 | P3 合理；若有跨用户共享目录场景实际可达 P2 |

## 3. 修复方案（四层防御，报告建议全采纳）

| # | 层 | 内容 | 工作量 |
|---|------|------|------|
| F1 | **输出转义（根因）** | 文件名 HTML 实体转义（`<>&"'`），三处上下文分别处理：元素体直接转义；URL 先 urlencode 再属性转义 | 小 |
| F2 | 事件绑定重构 | 文件名放 `data-*` 属性 + `addEventListener`，彻底移出内联 onclick（消除第 2 处上下文） | 小 |
| F3 | 入口白名单（纵深） | 上传/改名对文件名拒绝 `< > " '` 及控制字符（SFTP 面与 Web 面同规则；存量恶意名文件在列表页因 F1 已无害） | 小 |
| F4 | CSP 兜底 | `/f/` 页响应头加 `Content-Security-Policy: default-src 'self'; script-src 'self'`（禁内联脚本需配合 F2，渐进式先加 report-only 观察） | 极小 |

附带加固（顺手，不另立项）：rename 接口服务端同样校验新文件名（F3 同规则），防"改名投毒"。

## 4. 兼容性说明

- 正常文件名（中文/空格/括号等）**不受 F3 影响**，仅拒绝 HTML 元字符——测试回归将覆盖中文目录与文件（现有基线已含）
- F2 改动仅限列表页 JS 绑定方式，UI 行为不变
- 存量已落盘的恶意名文件：F1 生效后渲染为纯文本（无害），F3 不追溯删除（避免误删用户数据）
